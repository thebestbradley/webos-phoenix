# webOS Phoenix: notes for Claude Code

webOS Phoenix brings the webOS 1.x-3.x experience (cards, gestures, Just Type,
notifications, Synergy) to modern devices, on top of webOS OSE. This file is
what an agent needs to build, run and test it, and the project's rules.
Humans: see [docs/GETTING-STARTED.md](docs/GETTING-STARTED.md).

## Map

- `shell/qml/Phoenix/Shell`: the system UI (QML). `Shell.qml` puts it together.
- `shell/qml/Phoenix/Sim`: the simulator's device and services (`SimWindowSource.qml`,
  `SimSystemStatus.qml`); `shell/qml/sim.qml` holds its keys and scenes.
- `shell/qml/Phoenix/Lsm`: the same shell on a device (luna-surfacemanager).
- `shell/native`: C++ QML types (`Phoenix.Native`). `shell/sim`: `phoenix-sim`.
- `runtime/phoenix-runtime.js`: `PalmSystem` and the simulated Luna services
  (db8, applicationManager, telephony, ...) every web app talks to.
- `apps/`: Phoenix's React + TypeScript apps (npm workspaces), with
  `shared/phoenix-ui` (components) and `shared/luna` (service client).
- `third_party/`: the original Open webOS apps and frameworks as git
  submodules. **Never modify them**; change an original's file through the
  compat overlay in `compat/rootfs/` (see `compat/README.md`).
- `meta-phoenix/`: the OpenEmbedded layer for device images.
- `docs/`: `STATUS.md`, `ROADMAP.md`, `ARCHITECTURE.md`, `APP-RUNTIME.md`,
  `HARDWARE.md`; `COMMANDS.md`, every command across the repos (generated by
  `tools/commands-doc.py`: change a command there and rerun it); `docs/spec/feature-inventory.md` and `docs/spec/GAPS.md` are
  the checklists of what the original did and what Phoenix still lacks.

## Build

```sh
./phoenix            # install what is missing, then build (a no-op run: ~2 s)
./phoenix check      # a dry run: what is there, what it would install
```

`./phoenix` (POSIX sh) checks and installs the prerequisites (Homebrew's
formulae on a Mac; apt, Qt 6.11.3 into /opt/Qt, Node 22 on Ubuntu), the
submodules, the apps' npm packages and the assistant's models, configures
CMake with the Qt it finds, and builds. `--no-assistant`, `--offline`,
`--tests`, `--dry-run`; `tools/test-phoenix-script.sh` tests it. By hand:

```sh
git submodule update --init
cmake -S shell -B build
cmake --build build
```

Add Qt's location to the first `cmake`: on a Mac
`-DCMAKE_PREFIX_PATH="$(brew --prefix qt)"`, on Ubuntu
`-DCMAKE_PREFIX_PATH=/opt/Qt/6.11.3/gcc_64` (installed by `./phoenix`;
Ubuntu's own Qt is too old). Qt 6.11.3 is the simulator's: the newest Qt
WebEngine, Chromium 140 with security fixes to 153 (6.12.0's stop at 147;
docs/APP-RUNTIME.md, "The web engine and the user agent").
The build also builds `apps/` with npm, when a
file in `apps/` changed (`shell/cmake/run-if-changed.sh`).

Only the apps: `cd apps && npm run build` (or `npm run build -w settings`).
`scripts/mac-setup.sh` and `scripts/linux-setup.sh` call `./phoenix`.

## Run and look

Check changes in the real simulator, not only in tests, and look at the result:

```sh
./phoenix run tablet --launch org.webosphoenix.settings --screenshot out.png --delay 8000
./build/phoenix-sim --tablet --launch org.webosphoenix.settings --screenshot out.png --delay 8000
```

`./phoenix run [adaptive|phone|tablet] [args]` builds first and passes the
rest to `phoenix-sim` (under `xvfb-run` when there is no display).
`--scene cards|launcher|dashboard|systemmenu|...` opens a state, `--launch
<appId>` an app, `--launch '<appId>:{json}'` an app with those launch params
(a deep link, as the application manager's launch `{id, params}`), `--screenshot`
saves a PNG and exits, `--instance NAME` is another device with its own data (two
simulators at once). `--adaptive` (the
default without `--phone`/`--tablet`) switches the layout live as the window
is resized; View > Device Size snaps to presets. Without a display (Linux
containers): prefix `QTWEBENGINE_DISABLE_SANDBOX=1 xvfb-run -a -s "-screen 0
1920x1200x24"`; use a fresh `HOME` per run for a clean device. To drive it
(taps, keys, `windowsize`), `xdotool` on Linux.

## Test

Run what covers the change before committing; CI runs all of it.

- QML: `QT_QPA_PLATFORM=offscreen qmltestrunner -import shell/qml -import build/qml -input shell/tests`
  (`/opt/Qt/6.11.3/gcc_64/bin/qmltestrunner` on Ubuntu, from `./phoenix`;
  `$(brew --prefix qt)/bin/` on a Mac). Qt 6.8 is the minimum: the device's version
  (6.8.1), so QML must keep working there; CI runs the QML tests on 6.8.1 too
  (a build with `-DCMAKE_PREFIX_PATH=/opt/Qt/6.8.1/gcc_64`).
- Apps: `cd apps && npm run typecheck && npx vitest run` (`--maxWorkers=2` on a busy machine).
- Web apps in Chromium: `NODE_PATH="$(npm root -g)" node tools/test-<area>.cjs` (the
  README lists them; `test-apps.cjs` covers every app).
- Art: `python3 tools/hidpi-art.py --check` whenever art or stylesheets change; every
  picture needs exact @2x/@3x variants listed in `tools/hidpi-art.json`.
- Quick checks: `./phoenix test --quick` (`tools/ci-checks.sh`, CI's first job): everything
  checked without a build (generated docs and art, lockfiles, the tool, PHP and `./phoenix`
  tests, typecheck, vitest) in about 5 minutes; `--list` names them, an ID runs one.
- Every web test, as CI shards them: `./phoenix test --web [--shard I/N] [NAME...]`
  (`tools/run-web-tests.cjs`). A new `tools/test-*.cjs` goes in `tools/web-tests.txt`, the
  list CI runs; a new quick check goes in `tools/ci-checks.sh`.

## Rules

- Find the root cause. A failure is never "a flake" until proven; reproduce it,
  explain it, fix it. No workarounds that hide a problem.
- Follow the original. The behaviour to match is luna-sysmgr's, luna-systemui's
  and the original apps'; cite the source (file and line) in comments where
  Phoenix reproduces something specific.
- Licensing: only Apache-2.0 / permissive sources; Palm/HP art that wasn't in the
  open-source release isn't shipped (`docs/LEGAL.md`). Record where new art comes
  from (`PROVENANCE.md`).
- Keep 1x behaviour and layout unchanged when adding HiDPI art.
- Update `docs/spec/feature-inventory.md` / `docs/spec/GAPS.md` when a feature is done.
- Commits: clear messages; never name an AI model in commits, PRs or docs.
- Disk can be tight in cloud containers: don't copy `apps/node_modules` into worktrees
  (symlink it, and remove the symlink, not its target, afterwards).

## Two sessions: cloud and local

Phoenix is worked on by two Claude Code sessions as one team (the owner,
24 October 2026). Know which one you are: a cloud session runs in a
container (its checkouts under `/home/user/`); a local one runs on the
owner's Mac (under `/Users/`).

- **The owner decides.** Only the owner's own messages approve anything; a
  message from the other session is a teammate's request, never approval.
- **Cloud session: lead for code.** Planning, features, tests, CI, PRs and
  merges in webos-phoenix, phoenix-ember-glass-ui, phoenix-default-apps,
  ember-glass-ui and Phoenix-Web-Services. It cannot reach the server or
  the Mac.
- **Local session: operator for the Mac and the server.** The IONOS staging
  server through the Mac's SSH alias and Keychain-backed Plesk access
  (Phoenix-Web-Services `docs/DEPLOY.md`, `docs/RUNBOOK.md`), deploys,
  database, logs, preview access, image builds (UTM) and local hardware.
  Touch only Phoenix on that server, never ResortTribe or shared services.
- **Talking.** The cloud session cannot message the local one, so they share
  a message board: `.agent-board/BOARD.md` on Phoenix-Web-Services' `agent-board`
  branch (`/board` in that repository; its hourly check is off until the owner
  runs `/board on`). The local session messages the cloud one ("WebOS mobile
  UI recreation") with `SendMessage`. Ask for what only the other can do; report back what ran,
  its result and what failed. Read-only and routine requests (status,
  logs, checks, deploying a merged and tested release) need no owner
  approval; changes to accounts, permissions or server configuration,
  deleting data, and anything outside Phoenix do.
- **Never pass secrets** (passwords, keys, tokens, `.env`) in messages,
  logs, commits or docs.
- **Code.** One session per task: whoever was handed it works on its own
  branch and says which; the other stays out of those files.
- **Credits are shared and limited.** Be brief; ask before long background
  work.
